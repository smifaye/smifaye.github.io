We built a new CMS with a set of new components for content designers to use. I wrote the guidance that helps content designers use them well and accessibly.

## The problem

The new CMS came with new components and content designers needed principles to follow. Without them, the same component could end up used in different ways and some of those could make a page harder to use for people with accessibility needs.

## My role

I worked on all of the new components and created the guidance on how to use them. I worked with UX designers, software engineers and with the content designers who would use the components every day.

## What I did

### I named components by what the content is 

I renamed “revealables” to “targeted content”. The old name described how the component looks on a web page, not what the content is. Naming it by what it is means the component works across platforms - and it’s easier for a content designer to know when to use it.

### I wrote guidance that explains why 

For each component, the guidance covers when to use it, when not to and the reason. For example:

1. Callouts - Check you need one before you add it, because fewer callouts have more impact. Each new callout also needs a new heading level and more heading levels make a page harder to understand.
2. Targeted content - It’s interactive, because people have to click to read it, so it has a bigger effect on accessibility. For that reason, you can’t put targeted content inside targeted content.

### I wrote the accessibility guidance for content

It covers captions and transcripts for video, alt text for images (brief, descriptive and never starting with “image of”), leaving decorative images blank and structured headings.

### I set out how to write error messages

The guidance says to describe what has happened and tell people how to fix it. It lists vague messages to avoid, like “An error occurred”, “Select an option” and “Fill in the field”. 

It gives specific ones to use instead, like “Enter your first name” and “Select if you are British, Irish or a citizen of a different country”.

### We tested with content designers

Once the components were built into the CMS, we tested the functionality with the content designers who would use them. 

## The result

Content designers use the guidance in their daily work. It has led to:

- fewer questions about how to use components
- faster authoring
- more consistent pages
- better accessibility results
- positive feedback from content designers

## What I learned

Guidance works best when it explains the reason behind a rule. Content designers are more likely to follow a rule they understand and they can use their judgment in cases the rule doesn’t cover.
